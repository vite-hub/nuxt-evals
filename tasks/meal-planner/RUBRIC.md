# Meal planner rubric

How we grade a Meal planner app built from [PROMPT.md](PROMPT.md). Each check under a section passes, fails, or does not apply (n/a), and each section gets a score from 0 to 10.

Rules for graders:

- Grade outcomes and code. Never grade file layout for its own sake, and accept every correct form: hash or HTML5 history, Vue Router's file-based routes or a routes array, its experimental data loaders or plain composables, VueUse or the same thing written well by hand, `localStorage` or IndexedDB, a Web Worker or build-time preprocessing of the data, a service worker written by hand or generated by a build plugin, plain CSS or a CSS tool.
- The app has no backend. Grade it as a static build served by the production preview the README documents (usually `vite preview`). Browse at `http://localhost:<port>`.
- The recipe data is the agent's `data/` folder (20,289 recipes in about 19 MB, 136 ingredients; `data/README.md` has the fields, the densities and the US measures). Check numbers against it with a short Node script when a check needs them.
- Browser checks use Playwright. A fresh `browser.newContext()` has empty storage. Two pages of one context share `localStorage` and see each other's `storage` events, as two tabs do. `newContext({ timezoneId, locale, colorScheme })` sets the time zone, locale and color scheme; `newContext({ viewport: { width: 390, height: 844 }, hasTouch: true, isMobile: true })` is a phone; `page.clock.install({ time })` sets the clock; `page.emulateMedia({ media: "print" })` shows the print style; `context.setOffline(true)` takes the network away.
- "A cheap Android phone": open a CDP session (`page.context().newCDPSession(page)`) and send `Emulation.setCPUThrottlingRate` with `{ rate: 4 }`. Measure long tasks with a `PerformanceObserver` for `longtask` added by `page.addInitScript` before the page loads. Run each measurement three times and take the median.
- Grade against the prompt the agent got (its `PROMPT.md`). A check about a feature that prompt doesn't ask for is n/a.
- Each check names how to verify it: **run** (build the app, serve it, and test it in a browser), **read** (read the code), **both**, or **log** (the agent's session log).
- **M** marks a major check, **m** a minor one.
- Sources are the Vue, Vue Router, VueUse, Vite, Vitest and web platform docs.

## Scores

A section scores the weighted share of its checks that pass, times 10, with one decimal: a major check weighs 3 and a minor one 1. A check marked n/a counts as a pass. A check that can't be verified in the grading setup is marked **unverified**: it is reported, but it is neither a pass nor a fail, and the section is scored on the rest. A section whose checks are all n/a is left out.

The headline score, 0 to 10, is a weighted mean: the sections share 65% equally and Vite Doctor's score shares 10%, so the sections weigh 87% and Doctor 13%. A run that doesn't build or start scores 0.
